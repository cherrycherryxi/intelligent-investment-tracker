推荐项目：智能代码审查 Agent

项目定位：给定一个 GitHub PR，Agent 自动调用工具分析代码变更，用推理模型深度思考潜在问题，输出结构化审查报告。—— 恰好覆盖 MCP + Skills + 推理模型三个核心模块。
用户接入层
CLI 命令行 GitHub Webhook（可选） FastAPI REST
↓
Agent 调度层
任务规划（推理模型） 工具选择 上下文管理 Skills 路由
↓
MCP 工具层
fetch_pr_diff run_static_analysis search_codebase post_review_comment
↓
推理 & Skills 层
DeepSeek-R1 / Claude Sonnet code_review_skill security_check_skill CoT 截取
↓
评测 & 可观测层
LLM-as-Judge 评分 工具调用日志 延迟 & token 监控
不喜欢这个方向？其他可选主题：个人知识库 QA Agent（MCP 读文件 + RAG + 推理）、多工具数据分析 Agent（MCP 查数据库 + 画图 + 推理解读）。核心原则：三层都要有。

Week 7 结束时的验收标准

🐙
GitHub 仓库：公开可访问
有 README（含架构图 + Demo）、清晰的目录结构、可运行的 Quick Start。面试官打开 10 秒内能看懂这个项目在做什么。
🔧
MCP Server：至少 2 个真实工具
不是 Hello World 级别的 demo，而是在项目中实际被调用、有错误处理、有日志的生产级工具。
🧠
推理模型集成：有具体的工程决策
能回答「为什么这里用推理模型而不是普通模型」「budget tokens 怎么选的」—— 有工程判断，不只是 API 调用。
📊
评测报告：量化质量
10 个以上测试用例，有通过率、失败案例分析。能在面试中说「我的评测结果显示 X% 的任务成功率」。
✍️
技术博客：至少 1 篇已发布
有公开 URL，放进简历或 GitHub Profile。写作本身就是对空窗期最好的交代。
面试口径（现在就可以背）：「离开上一家公司后，我系统梳理了 2025 年 Agent 工程的演进，重点研究了 MCP 协议落地和推理模型的应用工程化，并独立做了〔项目名〕——一个融合 MCP Server、Skills 复用体系和 DeepSeek-R1 推理能力的 Agent 系统，配套写了评测框架和技术博客。」
